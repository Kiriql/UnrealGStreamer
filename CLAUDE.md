# CLAUDE.md

Плагин Unreal Engine 5.7 для двусторонней интеграции с GStreamer (источник и приёмник видео/аудио).
Цель: Fab Marketplace + GitHub-портфолио.

## Целевые платформы

- **Supported**: Win64, Linux, Mac, Android (включая Quest standalone).
- **Out of scope**: iOS (App Store запрещает динамические библиотеки, GStreamer-интеграция требует полностью статической сборки и конфликтует с UE AVFoundation; аудитория мала). Не предлагай и не реализуй iOS-код. Если в существующем коде есть iOS-ветки — оставь как есть, но не развивай.

## Текущее состояние

- Linux: zero-copy путь работает.
- Windows / Mac / Android: работает через копирование, zero-copy ещё не реализован.
- API писался "для себя" — нужна переработка под внешнего пользователя.
- Документации, демо-сцен, benchmarks, README для Fab — пока нет.

**При первом запуске в новой сессии**: просканируй репозиторий и обнови раздел "Архитектура" ниже фактическими именами модулей, классов и путями. Не выдумывай — если чего-то нет, отметь как TODO.

**Аудит существующего кода** (выполнить один раз, до начала любых новых задач): код писался итеративно "для себя" и работает, но не факт что оптимально. Пройдись по проекту и составь отчёт `docs/code-audit.md` со списком найденных проблем по категориям: (1) корректность и потенциальные баги, (2) утечки ресурсов (GStreamer refcount, GLib, UE handles), (3) thread-safety между GStreamer-потоками и game thread, (4) дизайн API и связность модулей, (5) очевидные места для улучшения производительности. **Не рефакторь сам** — только составь список с конкретными файлами/строками. ## Архитектура

Сжатая карта (заполнено из репозитория 2026-05-28). Подробности — `README.md` (поток данных) и `docs/architecture.md` (модуль, синхронизация, потоки, известные пробелы).

- **Модуль**: один runtime-модуль `GStreamerModule` (`GStreamerModule.Build.cs`, `Private/GStreamerModule.cpp`). Исходники скопированы из host-проекта; вынос в отдельный плагин (`.uplugin` + `Source/`-layout) запланирован, ещё не сделан. Шейдер `BGRAtoNV12.usf` будет скопирован (пока отсутствует). `Build.cs` содержит только ветку Linux. Детали — `docs/architecture.md`.
- **Zero-copy путь (Linux)**: `UGstH264AppSrcComponent` (`Public/Private/GstH264AppSrcComponent.*`). Механизм — Vulkan external memory + external semaphore (OPAQUE_FD) → импорт в CUDA → NVENC. Вся GPU-логика во вложенной `FVulkanExportResources` (`GstH264AppSrcComponent.cpp:45`).
- **Copy-путь (универсальный, кросс-платформенный по замыслу)**: отправка `UGstAppSrcComponent` (`ReadSurfaceData` GPU→CPU readback, `GstAppSrcComponent.cpp:101`); приём `UGstAppSinkComponent` + `FGstTexture` (`RHIUpdateTexture2D` CPU→GPU). **Точка копирования для замены на Win/Mac/Android** — `UGstAppSrcComponent::PushBufferAsync`.
- **GStreamer bus**: `FGstPipelineImpl::Start` поднимает `GMainLoop` в отдельном std::thread (`GstPipelineImpl.cpp:158`); bus-сообщения обрабатываются в `OnBusMessage` (`:169`) в контексте этого потока. Явного маршалинга bus → game thread нет.
- **Обёртки GStreamer**: `IGstPipeline/IGstAppSrc/IGstAppSink/IGstSample` (фабрики `CreateInstance()`, impl в `Private/Gst*Impl.cpp`). Public-заголовки используют opaque-указатели — GStreamer-типы не протекают; исключение — `Public/NvEncEncoder.h` тянет `<cuda.h>`/`nvEncodeAPI.h`.

## Стиль кода и коммуникации

- **Никаких типов GStreamer/GLib в public-заголовках** — только в `Private/` или через opaque pointer. Маркетплейс-сборка должна компилироваться без экспонированных GStreamer-хедеров.
- **Изоляция glib/gst-инклудов от UE-инклудов в `.cpp`.** Один TU не должен включать одновременно `CoreMinimal.h` и `<gst/gst.h>`/`<glib.h>`: UE объявляет глобал `extern FOutputDeviceError* GError` (`CoreGlobals.h`), glib — `typedef struct _GError GError`, конфликт ломает компиляцию любого glib-хедера с GError-параметром. Делаем split (как Linux-модуль): «glib-сторона» в отдельном `.cpp` (только `<gst/gst.h>`, без UE), UE-сторона дёргает её через узкий C-style header с plain-типами (`uint32_t`, `const char*`). Не использовать `#define GError ...`-обёртки. Подробности — `docs/research-log.md` (2026-05-30).
- **Подпапки в `Public/`/`Private/`.** Никогда не клади новый файл прямо в корень `Public/` или `Private/`. Создавай (или используй существующую) тематическую подпапку. Базовый набор: `Core/`, `Pipeline/`, `Components/`, `Texture/`, `Encoding/`, `ZeroCopy/<Platform>/`, `Shader/`, `ThirdParty/`. Категория — по ответственности класса, не по типу UE-объекта (не «всё что `UActorComponent` → в `Components/`», если файл по сути обёртка `gst_app_src` — это `Pipeline/`).
- **Нейминг при переносе из исходного модуля.** Не переноси имена слепо. Перед копированием — оценивай: интерфейсы должны жить в файлах `I*.h` (не `*Impl.h`); реализация — без отдельного `.h` где можно; имена компонентов не должны зашивать конкретный backend (например `GstH264AppSrcComponent` — кандидат на `GstHWVideoSourceComponent`, H264 — деталь реализации). Если переименование улучшает читабельность — предложи; если меняешь имя — сделай за один проход во всех файлах, не оставляй смесь.
- Комментарии в коде не добавляй, если я не попросил. Исключение — Doxygen для public API.
- В ответах: коротко, по делу, на русском, технические термины на английском. Без эмодзи, без disclaimer'ов, без "надеюсь это поможет".

## Marketplace-критичные ограничения (учитывай всегда)

- Не бандлить GPL-плагины GStreamer (`bad` смешанный, `ugly` GPL, `libav` по умолчанию тянет GPL-кодеки). Базовый набор — `core`, `base`, `good` под LGPL.
- Все бандлируемые бинарники — через `RuntimeDependencies` с `StagedFileType.NonUFS`, делейлоад на Win через `PublicDelayLoadDLLs`.
- `BuildPlugin` для installed-engine должен проходить чисто — Fab валидирует именно его, не project build.

## Проверка работы

- При изменениях в Build.cs или ThirdParty: пересобрать через `BuildPlugin`, не только project-сборку.
- При изменениях в pipeline-логике: прогнать demo-сцены на всех целевых платформах, на которых уже работает текущий код.
- Для zero-copy: до/после benchmarks обязательны — без чисел изменение не считается завершённым.
